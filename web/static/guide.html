AGENT SKILL GUIDE · ALL ENVIRONMENTS

이미 만든 ADK 에이전트에 Agent Skill 적용하기

adk create 또는 직접 작성한 app/agent.py 프로젝트에 agent-production-readiness 스킬을 설치하고, 공통 4단계 프롬프트만으로 프로덕션 체크리스트 정적 진단 → 변경점 검토 → 보완 적용 → 리포트 생성까지 마치는 실전 가이드입니다. Agent Runtime · Cloud Run · GKE 어느 환경이든 사용법은 동일하며, 스킬이 프로젝트 설정(deployment/)에서 배포 환경을 자동 감지합니다. (Antigravity CLI agy · Gemini CLI · Claude Code · Cursor 공통)

① 설치 · 사전 준비 ② 4단계 기본 프롬프트 ③ 내 조건 맞춤 프롬프트 생성기 ④ 상황별 추천 프롬프트 ⑤ 수정 범위 · 플랫폼 Skill
🎯 선택 적용 · 1개 Feature씩 순차 반영 전체 Best Practice를 먼저 진단·설명하되 임의로 일괄 수정하지 않고, 사용자가 고른 항목만 설정을 물어본 뒤 1개씩 diff 승인 → 적용합니다.
🔒 기존 코드 원본 주석 보존 에이전트 로직·프롬프트는 건드리지 않으며, Memory Bank 등 코드 배선이 필요할 때도 원본을 # [ORIGINAL ...] 주석으로 남긴 diff 승인 후에만 반영합니다.
📚 일반 플랫폼 BP는 별도 Skill 연계 Preview 항목은 통과를 막지 않으며, 프로브·PDB·알림·네트워크·Non-Root 등은 google/skills 플랫폼 Skill로 이어서 점검합니다.

1 사전 준비 (최초 1회 · 약 3분)

로컬 PC 또는 Cloud Shell에서 agents-cli + 공식 Agents CLI 스킬, agent-production-readiness 스킬, 그리고 Google Cloud 플랫폼 Agent Skills(google/skills)를 설치합니다. 기존 ADK 프로젝트에 배포 구성(deployment/)이 없다면 agents-cli scaffold enhance로 뼈대만 추가합니다.

1-1. Google Agents CLI (agents-cli) 및 공식 Agents CLI Skill 설치

bash · agents-cli 설치(업그레이드) + 공식 Agents CLI 스킬 글로벌 설치 
command -v uv >/dev/null 2>&1 || curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv tool install google-agents-cli --upgrade
agents-cli setup --skip-auth
agents-cli --version

1-2. agent-production-readiness + Google Cloud 플랫폼 Agent Skills (google/skills) 설치

bash · GitHub에서 최신 agent-production-readiness 스킬 및 Google Cloud 플랫폼 스킬 일괄 설치 
rm -rf ~/.gemini/skills/agent-production-readiness && mkdir -p ~/.gemini/skills
curl -fsSL "https://github.com/kiwonilee/production-ready-agent-platform/archive/refs/heads/main.tar.gz" \
  | tar -xz -C ~/.gemini/skills/ --strip-components=2 production-ready-agent-platform-main/skills/agent-production-readiness

# 대상 환경(agent_runtime | cloud_run | gke)의 공식 Google Cloud Agent Skills(google/skills) 설치 + doctor 검증
python3 ~/.gemini/skills/agent-production-readiness/scripts/prod_ready.py doctor . \
  --target agent_runtime \
  --install-platform-skills \
  --skills-dir ~/.gemini/skills

최신 스킬 소스·문서 확인은 GitHub 저장소 (skills/agent-production-readiness) ↗에서 바로 볼 수 있습니다.

1-3. 기존 ADK 프로젝트에 배포 구성(deployment/)이 없는 경우

순수 adk create나 직접 작성한 app/agent.py만 있는 프로젝트라면 아래 명령어로 배포 뼈대(Terraform · Cloud Build · Dockerfile)만 덧붙이세요. 기존 app/agent.py는 Skipping (your code)로 그대로 보존됩니다. (이미 deployment/ 폴더가 있다면 이 단계는 건너뜁니다.)

bash · deployment/ 뼈대 추가 (--deployment-target: agent_runtime | cloud_run | gke) 
cd <내-ADK-프로젝트-폴더>

# 배포 대상에 따라 agent_runtime | cloud_run | gke 중 하나 지정
agents-cli scaffold enhance . \
  --deployment-target agent_runtime \
  --cicd-runner google_cloud_build \
  --region us-central1

2 표준 4단계 워크플로우 & 기본 추천 프롬프트

프로덕션 환경은 팀마다 다르기 때문에, 이 스킬은 ① 전체 Best Practice 진단 + 항목별 1줄 설명(Find) → ② 사용자가 원하는 항목 선택(Select) → ③ 항목별 맞춤 설정 질문 · Diff · Apply (1개씩 순차 진행) → ④ 최종 리포트 · 배포 흐름으로 동작합니다.

🛡️ 실전 적용 원칙 (선택 · 맞춤 설정 · 1개씩 안전 적용): 임의로 전체 항목을 한꺼번에 고치지 않습니다. 각 항목을 적용하기 전에 필요한 설정(예: Agent Gateway Egress/Ingress/Both · DRY_RUN/ENFORCED · Model Armor, Cloud Run 전용 SA vs Agent Identity 등)을 먼저 물어보고, 1개 Feature씩 diff 승인 후 적용합니다. (실습 환경에서 전체 항목을 한 번에 체험해 보고 싶다면 /lab 핸즈온 실습 ↗을 이용하세요.)
STEP 1 · FIND
진단 · 항목별 1줄 설명
doctor + Best Practice 전체 scan + 각 항목이 무엇인지 1줄 설명 (수정 없음)
STEP 2 · SELECT
원하는 항목 선택
진단표를 보고 실제로 도입할 항목 ID(예: CR-F1, CR-S1)만 직접 선택
STEP 3 · FEATURE LOOP
항목별 설정 · Diff · Apply
선택 항목을 1개씩 순차 진행: 필요 옵션 질문 → 단일 diff 승인 → apply
STEP 4 · REPORT & DEPLOY
리포트 · 배포 · 플랫폼 Skill
uv.lock · 재검사 · READINESS_REPORT 생성 + 배포 · google/skills 연계

Step 1. 전체 진단 + 항목별 1줄 설명 (doctor → scan, 수정 없음)

PROMPT 01 · Find — Best Practice 진단 및 항목별 설명 리포트 
agent-production-readiness 스킬로 현재 ADK 프로젝트를 점검해줘.
배포 환경은 자동 감지하고, 파일은 수정하지 말고 각 항목의 1줄 설명·공식 근거 링크와 함께 진단 결과표(핵심 판정 + 선택형 Add-on)만 먼저 보여줘.

Step 2. 적용할 항목 선택 → 항목별 설정 질문 & 단일 Diff 미리보기

진단표를 보고 필요한 항목만 골라 말하면, 스킬이 1개 항목씩 필요한 설정(예: Gateway 방향·모드, 평가 기준 점수, 신원 방식 등)을 묻고 원본 주석 보존(# [ORIGINAL ...]) diff를 제시합니다.

PROMPT 02 · Select & Feature-by-Feature Configure / Diff 
진단표 중 CR-F1, CR-S1, CR-OB1 항목을 적용하고 싶어.
한 번에 다 고치지 말고 1개 항목씩 필요한 설정을 물어본 뒤, 각 항목의 diff를 먼저 보여줘.

Step 3. 항목별 승인 후 적용 → 모든 선택 항목 완료 후 재검사 · 리포트

PROMPT 03 · 항목별 Apply 승인 + 최종 재검사 · 리포트 생성 
방금 보여준 diff 확인했어. 이 항목을 적용하고 다음 선택 항목으로 넘어가줘.
(모든 선택 항목 적용이 끝나면 uv.lock 갱신, 최종 재검사, READINESS_REPORT 생성까지 진행해줘.)

Step 4. GCP 배포 명령어 정리 + 일반 플랫폼 BP 추가 점검

PROMPT 04 · 배포 명령어 + 플랫폼 Skill 연계 
현재 프로젝트의 GCP 배포 및 검증 명령어를 정리해주고, 설치된 Google Cloud 플랫폼 스킬로 일반 인프라 설정도 이어서 점검해줘.

4 상황별 추천 프롬프트 모음

      
특정 목적이나 환경에 맞춰 바로 복사해 쓸 수 있는 실전 프롬프트 레시피입니다.


      

        

          

            환경 미정 · 비교 추천
            
① 배포 환경 추천 + 즉시 정적 진단

            
Agent Runtime · Cloud Run · GKE 중 어디에 올릴지 아직 못 정했을 때 사용합니다.

          

          

            

              PROMPT · 환경 추천 + scan
              
            

            
현재 ADK 프로젝트 코드를 분석해서 Agent Runtime, Cloud Run, GKE 중 어떤 배포 환경이 가장 적합한지 근거와 함께 추천해줘.
그리고 추천한 환경을 기준으로 agent-production-readiness 스킬의 정적 진단(scan)을 수정 없이 바로 실행해서 표로 보여줘.

          

        


        

          

             Agent Runtime
            
② Agent Identity + Agent Gateway 중심

            
관리형 런타임에서 전용 신원과 외부 MCP 호출 통제를 안전하게 도입할 때 사용합니다.

          

          

            

              PROMPT · Agent Runtime 보안·거버넌스
              
            

            
agent-production-readiness 스킬로 Agent Runtime 기준 진단 및 diff를 보여줘.
- 전용 신원(Agent Identity)과 외부 MCP 호출 통제(Agent Gateway DRY_RUN 모드)를 우선 적용하고,
- 트레이스에 프롬프트 본문이 남지 않는지도 확인해줘.

          

        


        

          

             Cloud Run
            
③ 인증 호출 · 영속 세션 · Cloud Trace

            
서버리스 컨테이너 배포 전 필수 보안과 멀티턴 세션·트레이스를 점검할 때 사용합니다.

          

          

            

              PROMPT · Cloud Run 프로덕션 점검
              
            

            
agent-production-readiness 스킬로 Cloud Run 기준 정적 진단과 diff를 보여줘.
공개 호출 차단, 전용 신원·최소 권한, 영속 세션, Cloud Trace 설정을 중점적으로 확인해줘.

          

        


        

          

             GKE
            
④ 긴 응답 보호 + AI 코드 격리 (Substrate / Sandbox)

            
GKE에서 스트리밍 응답 보호와 격리 샌드박스를 구성할 때 사용합니다.

          

          

            

              PROMPT · GKE Agent Substrate / Sandbox
              
            

            
agent-production-readiness 스킬로 GKE 기준 진단 및 diff를 보여줘.
긴 스트리밍 응답 보호(종료 유예 180초)와 AI 생성 코드 격리·유휴 일시정지(Agent Substrate 권장, Autopilot이면 Agent Sandbox 대안) 기준으로 점검해줘.

          

        


        

          

            부분 적용 · CI/CD & Evaluation
            
⑤ CI/CD 파이프라인 · 평가 게이트만 추가

            
다른 설정은 그대로 두고 품질 평가 게이트(*-D1, *-D2)만 먼저 도입할 때 사용합니다.

          

          

            

              PROMPT · 평가 게이트 부분 적용
              
            

            
agent-production-readiness 스킬로 전체 수정은 하지 말고,
CI/CD 파이프라인과 품질 평가 게이트(기준 점수 4.0)만 점검해서 diff를 먼저 보여줘.

          

        


        

          

            사용자 위임 인증 · Preview
            
⑥ Jira · GitHub 등 사용자 대신 외부 도구 호출

            
정적 API 키/PAT를 제거하고 Agent Identity auth manager(3-legged OAuth)로 전환할 때 사용합니다.

          

          

            

              PROMPT · 사용자 위임 인증 (delegated)
              
            

            
이 에이전트는 사용자 대신 GitHub와 Jira를 호출해.
agent-production-readiness 스킬로 정적 API 키나 토큰이 남아 있는지 점검하고, 사용자 위임 인증 전환 가이드를 코드 예시와 함께 알려줘.

            🔒 비즈니스 로직 보존
            app/agent.py (프롬프트 · 도구 로직)
            비즈니스 로직과 프롬프트는 변경하지 않습니다. 단, Memory Bank(*-F2)를 선택하면 ADK 읽기 도구(preload_memory)와 저장 콜백(after_agent_callback) 배선이 필요하므로 원본을 # [ORIGINAL before prod-ready *-F2] 주석으로 보존한 diff를 먼저 보여주고 사용자 승인 후에만 반영합니다.
          

          

            🛠️ 자동 패치 가능
            app/app_utils/services.py · app/fast_api_app.py · pyproject.toml · Dockerfile · deployment/terraform/single-project/*.tf · cicd/*.tf · deployment/k8s/*.yaml · tests/eval/ · .cloudbuild/staging.yaml
            항상 diff로 먼저 확인한 뒤 사용자 승인 후에만 적용합니다.
          

          

            📋 안내 전용 (Guidance)
            *-D1 (CI/CD 파이프라인 생성) · CR-S4 (Agent Gateway for Cloud Run) · AR-S4 / CR-S5 (코드 격리) · AR-S5 / CR-S6 / GKE-S5 (사용자 위임 인증)
            상태를 판정하고 정확한 설정 가이드·명령어만 안내하며 임의로 파일을 덮어쓰지 않습니다.
          

          

            📚 플랫폼 Skill 위임
