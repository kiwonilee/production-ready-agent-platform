    배포 환경 선택

    먼저 배포 환경을 선택하세요. 선택한 환경에 맞춰 Step 1(실습 환경 준비)부터 ADK 기반 Agent 스캐폴딩 · 배포 · 런타임 점검 · 정리까지 해당 환경의 내용만 표시됩니다. Step 1 이후에는 이 화면이 숨겨지고 선택한 환경이 유지되며, 좌측 Step 0에서 언제든 바꿀 수 있습니다.

    🔒 환경을 바꿔도 에이전트 코드는 바뀌지 않습니다

    어떤 환경을 선택해도 에이전트 코드(ADK app/agent.py)는 그대로입니다 — 환경에 따라 달라지는 것은 배포 구성(agents-cli scaffold create / enhance --deployment-target, Terraform·매니페스트)뿐입니다.

    정확히 무엇이 바뀌나요? (scaffold create / enhance · Agent Skill 적용 범위)
    • agents-cli scaffold create로 생성되는 app/agent.py는 어느 타겟이든 동일하며, 나중에 agents-cli scaffold enhance로 타겟을 전환할 때도 app/agent.py를 Skipping (your code)로 건너뛰고 선택한 환경의 배포 구성(Terraform 템플릿 · CI/CD 파일)만 갱신합니다.
    • agent-production-readiness 스킬의 기본 적용(apply)도 app/agent.py의 비즈니스 로직·프롬프트를 건드리지 않습니다. 단, Memory Bank(*-F2)를 선택한 경우에만 ADK 읽기 도구(preload_memory)와 저장 콜백(after_agent_callback) 배선이 필요하므로 원본 라인을 # [ORIGINAL before prod-ready *-F2] 주석으로 보존하고 사용자 승인 후에만 반영합니다.
    • 스킬이 선택한 체크리스트 항목에 따라 보완하는 주요 파일은 아래와 같습니다.

      • app/agent.py (Memory Bank *-F2 선택·승인 시에만) — preload_memory · after_agent_callback 비파괴 주석 보존 배선
      • pyproject.toml — Cloud Run · GKE: google-adk[gcp,otel-gcp] 의존성
      • Dockerfile — Agent Runtime: Agent Gateway TLS 루트 CA 신뢰 설정

    Antigravity CLI는 같은 폴더에서 agy -c 명령으로 직전 대화를 그대로 복구할 수 있습니다. Agent Runtime 배포는 서버 측에서 계속 진행되므로 agents-cli deploy --status로 완료를 확인하세요.
    
          
    
        
    

        
    
          Q3. 배포 중 RUN uv sync --frozen 오류가 발생합니다.
          
    
            
    apply 패치 후 pyproject.toml이 갱신되므로 배포 전 프로젝트 루트에서 uv lock을 1회 실행해 lockfile을 동기화하세요.
    
          
    
        
    

        
    
          Q4. 터미널에서 복사한 JSON을 붙여넣을 때 줄바꿈이 깨져도 되나요?
          
    
            
    네, Web Workbench 백엔드가 터미널 하드 줄바꿈으로 @sha256:... 중간에 들어간 제어문자를 자동으로 정규화하여 파싱하며, GKE의 멀티-JSON 스트림(kubectl get ... -o json 여러 개 연결)도 자동 병합합니다.
    
          
    
        
    

        
    
          Q5. (GKE) agent-gateway.yaml 적용 시 CRD 없음 오류나 PSS restricted 거부·Autopilot 충돌이 발생합니다.
          
    
            
      
              
    • Agent Gateway for GKE CRD 없음: 공식 Agent Gateway for GKE(GCPAgentGateway, GCPBackend, GCPEgressPolicy, GCPAuthzPolicy v1, GCPExtensionBinding v1)는 GKE ≥ 1.37.2-gke.1042000 (Rapid 채널), Preview 리전(us-central1 / europe-west1), Step 1-3의 9개 공식 API, 그리고 리전 proxy-only 서브넷이 선행되어야 합니다.
      • 
              
    • Agent Substrate + Autopilot 충돌: Agent Substrate(ate.dev/v1alpha1)는 GKE Standard ≥ 1.37 전용입니다. Autopilot 클러스터에서는 Standard Pods 또는 Agent Sandbox를 사용하세요.
      • 
              
    • PSS restricted 적용 후 Pod 스케줄링 거부: 반드시 Non-Root securityContext가 반영된 terraform apply(또는 Deployment 업데이트)를 먼저 완료한 뒤 Namespace에 pod-security.kubernetes.io/enforce=restricted 라벨을 부착해야 합니다.
